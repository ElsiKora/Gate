## Goal

The core moves from `0.2.0` to `0.2.1`, and so do the two plugins that changed since `v0.2.0`, `git`
and `nestjs`; every other plugin stays at `0.2.0`. Each changed changelog has its `0.2.1` section,
dated the day of the release, so that the tags `v0.2.1`, `plugin-git-v0.2.1` and
`plugin-nestjs-v0.2.1` equal the Cargo versions the release and plugin workflows check. The shape is
that of the 0.2.0 release (T-035, merge `89c42c7`).

## Scope

1. On a branch from `main` at `340cf8b`: the workspace version, the git and nestjs plugins'
   versions, and `Cargo.lock` by `cargo update --workspace --offline`. A crate that inherits the
   workspace version but is released as a plugin that stays at `0.2.0` keeps `0.2.0`.
2. The root `CHANGELOG.md`: `Unreleased` becomes the patch heading `## [0.2.1](compare link) (date)`,
   with the upgrade note in the place of 0.2.0's and each entry linked to the commit that made it.
   The git and nestjs changelogs get their `0.2.1` sections the same way.
3. Every `0.2.0` in the tree is judged: where it means the current release (README, the guides, the
   issue template, a test or fixture that pins the running core), it says `0.2.1`, or the running
   version where a test can read it. A `0.2.0` that means that release, the plugin interface
   `gate:plugin@0.2.0`, or the pin of a plugin that stays at `0.2.0` stays.
4. No other change.
