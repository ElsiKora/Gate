## Goal

The workspace, the core and every plugin move from `0.1.0-rc.1` to `0.1.0`, and every changelog has a
`## 0.1.0` section that says what the release holds, so that tags `v0.1.0` and
`plugin-<name>-v0.1.0` match the Cargo versions the release workflows check.

## Scope

1. On a branch from `release/v0.1.0`: the version in every crate and plugin; `Cargo.lock` by
   `cargo update --workspace --offline`; the root `CHANGELOG.md` and each plugin's changelog get
   `## 0.1.0`, written from the merged task files (what a user can now do, in English, with no task id,
   no consumer, product or person named).
2. Docs that show a version in an example (`ElsiKora/Gate:<plugin>@0.1.0`) already say `0.1.0`; fix any
   that say `rc`.
3. No other change.

## Done when

- `grep -rn 'rc\.1' --include=Cargo.toml --include=CHANGELOG.md .` prints nothing.
- `cargo fmt --all --check`, `cargo clippy --locked --workspace --all-targets -- -D warnings`,
  `cargo test --locked --workspace`, `cargo deny --locked check` and `cargo build --release --locked`
  all exit 0 in the gates on the pushed commit.
- Do not edit docs/plan.md and push no tag; the lead tags.
