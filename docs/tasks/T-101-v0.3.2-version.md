- **The code since `v0.3.1` changes exactly the five.** Built on one host, `v0.3.1` and `main`
  give the same bytes for `agents`, `ci`, `docker`, `docs`, `git`, `markdown`, `node` and
  `repository`, and different bytes for `cdk`, `frontend`, `ledger`, `nestjs` and `typescript`;
  the `main` builds of the five equal T-098's builds at `a15a3180`.
- **The version bump changes the bytes of all 13 builds.** Every tip build differs from its `main`
  build, the eight plugins that stay at `0.3.0` too, with the same size or a few bytes apart
  (`docs` +133, `ledger`, `markdown` and `repository` +69, `node` -69, `frontend` +1, the others
  0). The only difference between `main` and the tip that a component compiles is the versions:
  the workspace crates every plugin depends on (`gate-sdk`, `gate-typescript`,
  `gate-agents-format`) move from 0.3.1 to 0.3.2. The likely cause, not traced further: cargo's
  crate metadata hash takes a crate's version, and symbol names and code layout depend on it. So
  a plugin built from a later core
  release does not give its earlier released bytes; the eight keep their `plugin-<name>-v0.3.0`
  assets and are not built again.
- **The released assets are not comparable here.** They are built on the `ubuntu-24.04` runner,
  and a plugin module differs between the Linux and the macOS host (`reproducible.yml`), so every
  local build differs from every released asset. The branch's own `Reproducible` run on `b13b28f`
  (run 45280753746) built all 13 twice on Linux and passed, but its step summary with the Linux
  sha256 is shown only to a signed-in account, and this task uses no token.
