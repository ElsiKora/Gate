# `agents/agents-block`

The table of rule files in the managed block of `AGENTS.md`.

## What it writes

The text between `<!-- gate:begin agents -->` and `<!-- gate:end agents -->` in `entry`:

- the line ``Generated by `<command-text>` from `<root>/rules`; edit the rule files, not this block.``,
- a table with one row per rule file (`Area`, `Rules` as a link titled by the file's `title` or
  name, `Applies` as `always` or its backticked globs, `Owner`), aligned the way Prettier prints a
  table while it fits in 100 columns and compact beyond; a `|` in a title or glob is escaped as
  `\|`,
- and, when some file applies always, the list `Always-apply rules:` of their links.

Links are relative to `entry`: with `entry = "docs/AGENTS.md"` a rule file
`docs/agents/rules/api.md` is linked as `agents/rules/api.md`. The rest of the file is kept byte
for byte. Markers that are missing, repeated or reversed are a finding of
`gate/sync#agents/agents-block` at the first marker's line.

When `entry` is not tracked, the generator seeds it: the title `# Agent instructions`, one line on
what the file is, and the block between its markers, filled as above. `gate sync` writes a seed only
where nothing exists, so an `AGENTS.md` a person wrote and has not added to git yet is left alone,
and `gate sync --check` never reports it. Once the entry is tracked, the generator writes only
between the markers.

`<root>/rules` with no rule file is a finding of `gate/sync#agents/agents-block`, in `gate sync`
and in `gate sync --check`: the block is emptied when the entry has the markers, and nothing is
written otherwise. Create a rule file or point `root` at the agent docs. Rule files are never seeded: each
needs an `area` and an `owner` that names a decision of the project's ledger.

A project that does not want the block removes the generator from `[generate]`.

## Options

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `root` | string | `"docs/agents"` | The directory of the agent instructions. |
| `entry` | string | `"AGENTS.md"` | The file that holds the block, relative to the project, written plainly: a leading `/` or a `.`, `..` or empty segment is refused. |
| `command-text` | string | `"bin/gate sync"` | The command the block names as the one that writes it. |

## Example

```md
<!-- gate:begin agents -->

Generated by `bin/gate sync` from `docs/agents/rules`; edit the rule files, not this block.

| Area  | Rules                                 | Applies           | Owner       |
| ----- | ------------------------------------- | ----------------- | ----------- |
| `API` | [API rules](docs/agents/rules/api.md) | `src/api/**/*.ts` | `D-API-001` |

<!-- gate:end agents -->
```
