# `agents/adapters`

The Claude Code adapters of the rule files and copies of the skills.

## What it writes

For each rule file `<root>/rules/<stem>.md`, the adapter `.claude/rules/<stem>.md`: a `paths:` front
matter block with each glob (only for `applies: globs`), the line
`<!-- Generated by gate sync from <rule file>; edit the canonical file. -->`, a blank line, and
the rule file's body after its front matter. Claude Code documents `@` imports only for
`CLAUDE.md` and `AGENTS.md`, so the adapter copies the text instead of importing it.

The stem is the file name without its one `.md` extension, in any case: `a.md.md` gives
`.claude/rules/a.md.md`. A rule file without valid front matter gets no adapter, since its scope is
unknown (`agents/rule-registry` reports the file). Two rule files whose adapter paths are equal
ignoring case get none; each is a finding of `gate/sync#adapters` naming both.

Every tracked file under `<root>/skills/` is copied byte for byte to the same place under
`.claude/skills/`.

The generator owns `.claude/rules/**` and `.claude/skills/**`: `gate sync` deletes a tracked file there
that it does not write, and `gate sync --check` reports one as `gate/sync#adapters`.

Paths are relative to the project. The adapter directory is always `.claude`, where Claude Code
reads it; it is not an option.

## Options

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `root` | string | `"docs/agents"` | The directory of the agent instructions. |

## Example

`docs/agents/rules/api.md` with `applies: globs` and `globs: ["src/api/**/*.ts"]` gives
`.claude/rules/api.md`:

```md
---
paths:
 - "src/api/**/*.ts"
---

<!-- Generated by gate sync from docs/agents/rules/api.md; edit the canonical file. -->

# API rules
...
```
